循环之上

一件事，
拆成几步来做？

循环是心跳——AI 一遍遍「想一步、做一步」。
工作流是骨架——决定问几次、先问什么、怎么配合。

先分清两个词。

它们都用到 AI，但「谁来定路线」不一样。

🗺️
工作流 · Workflow

路线提前画好——程序员写死「先 A 再 B 再 C」。 AI 只负责每一步怎么答，不负责改路线。

输入 → 步骤 A → 步骤 B → 输出
🤖
智能体 · Agent

路线现场想出来——AI 自己决定下一步干嘛、用哪个工具。 灵活，但也更难预测。

输入 → AI 自己琢磨 → 输出

Anthropic 的总纲： 从简单开始，能用工作流就别上 Agent。

模式 #1

提示链

一步接一步，做完再做下一步

什么时候用

任务能拆成固定的几步，顺序不会变——比如先列大纲、再写正文、最后润色。

有什么好处

每一步只干一件事，更简单、更好查、出了问题也好定位。

生活类比：像做菜：先洗菜 → 切菜 → 下锅，顺序固定。

可以叠着用。

五个模式是积木，不是五选一。常见搭法如下：

路由→提示链

先判断问题类型，再走该类专属的多步流程

编排者→并行化

包工头拆好活，几个工人同时干

提示链→评估

流水线跑完，最后请审稿人把关改稿

并行→投票 → 链

多路同时出方案，投票选最好的，再统一排版

三个反模式，
要避开。

生产环境里最常见的踩坑。

🦣
一个 Agent 包打天下

把所有工具和职责塞进一个智能体。难调、难测，一出错就乱套。

🏗️
还没试简单方案就堆复杂度

简单流程明明够用，却先造一套复杂的「规划流水线」。

🕳️
出了问题看不见

没有日志、没有记录、没有指标——坏了只能瞎猜。

跟我们手搓
有什么关系？

1

最小的 Agent 循环 = 最简的智能体。这五种模式是「循环之上还能怎么组织」，不必一开始就全上。

2

评估器对应「评估者—优化者」；自我改进是它的升级版——写手改稿，审稿人把关。

3

记住总纲：先简单，用评估去优化，只有简单方案真的不够用时，再加复杂度。
