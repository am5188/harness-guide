第 3 章 · 剥到最细

想一步，
做一步，看结果。

这就是智能体循环的核心。模型负责想， Harness 负责动手和收尾。

先记住一句话

模型只负责每一步怎么想。

读文件、跑命令、记历史、问你要不要批准——全是 Harness 的活。

OpenAI 说过：让它不只是「傻循环」的，是沿途 Harness 管的一切。

循环本身很笨，聪明全在模型里；但能不能真的把事做完，看 Harness 管得好不好。

一个回合里，
究竟发生了什么？

Turn（回合）：你发一句话，到 AI 回完并停下，算一整轮。 点「下一步」，跟着走一遍。

步骤 1 / 7
你
你发消息
比如：「帮我修这个 bug」

拆开看，就是 TAO 三步。

像做菜：先想菜谱（Thought），再下锅炒（Action），尝一口咸淡（Observation）。

T
Thought · 想

模型读上下文，决定下一步：直接回答，还是调用工具？

A
Action · 做

Harness 真的去执行——打开文件、跑测试、搜网页。

O
Observation · 看

工具跑完的结果塞回对话，模型据此再想下一步。

没有工具要调了？模型给出最终回复，这一回合结束。
还有事没做完？回到 T，继续转。

最容易漏掉的一点

循环必须知道：
什么时候停。

没有停止条件，就会无限转圈、烧光 token、卡死不动。

1
模型不再要工具，只给文字
最常见——它觉得活干完了
2
达到最大回合数
兜底保险，防死循环（新手可先设 50 轮）
3
上下文 / token 预算满了
该压缩历史或换策略了
4
收到明确的「完成」信号
或遇到无法恢复的报错

三层概念，
用聊天软件来理解。

OpenAI Codex 把对话拆成三个词。点下面三个标签，看它们怎么一层套一层。

🧵 Thread · 整段对话
🔄 Turn · 一轮
你：修这个 bug
读 main.py
改了两行代码
跑测试通过
AI：修好了
🔄

Turn · 一轮

你发一次话，到 AI 干完并停下，算一整轮

生活类比：你问「帮我修 bug」，对方读文件、改代码、跑测试、最后说「修好了」——这一整段算一轮 Turn。

生命周期：回合开始 → 一串 Item 依次出现 → 回合结束

为什么聊着聊着
就越来越贵？

每一轮新对话，都会把之前所有回合的历史重新塞进 Prompt—— 包括每一次工具调用和返回结果。

第 1 轮
你的消息 + 10 次工具调用 + 回复 ≈ 8k tokens
↓ 全部带进下一轮
第 2 轮
8k 历史 + 新消息 + 15 次工具 ≈ 24k tokens
↓ 继续膨胀
第 5 轮
上下文快满了 → 需要压缩（compaction）历史

Codex 的做法：token 超阈值时，把冗长历史换成更短的摘要，腾出空间继续干活。

危险动作，
先问你一句。

删文件、改生产配置这类事，Harness 会暂停当前回合，弹窗等你点头。 这叫人在环中（Human-in-the-loop）。

AI 要删文件
→
Harness 暂停回合
→
弹窗：允许吗？
→
你点「允许」
→
继续执行

审批开关放在 Harness 层，不写死在循环里——自主和监督可以分开调。

Codex 怎么拆的？

核心逻辑和界面分开，所有客户端共用同一套 Harness。

Codex Core · 心脏
  • ·智能体循环
  • ·线程管理
  • ·工具执行
  • ·配置与鉴权
App Server · 接口层

用统一协议包一层，谁都能连

CLIVS CodeWebmacOSJetBrains

同一个模型，Harness 不同，体验就不同——
所以 Codex 在自家界面上往往比通用聊天窗口更能干活。

自己搓的时候，
记住这三条。

1

先把最小循环跑通，再加停止条件、token 预算、审批闸门

2

分清 Item / Turn / Thread——哪怕最小实现，也把「一条消息」「一轮对话」「整段会话」拆开

3

历史用追加写文件存下来，以后才能恢复、压缩、断点续聊
